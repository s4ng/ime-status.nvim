1. INTRODUCTION                                       *ime-status-introduction*

ime-status.nvim shows the current keyboard input method (한 / EN / あ / 中) in
the statusline. It reads the current input source straight from the OS —
in-process via LuaJIT FFI on macOS and Windows. The result is cached and
refreshed asynchronously on a timer and on mode changes. It is
statusline-agnostic: it merely exposes a fast getter.

==============================================================================
2. REQUIREMENTS                                       *ime-status-requirements*

Just Neovim. On macOS and Windows the plugin queries the IME in-process
through the built-in LuaJIT FFI: no companion binary to install, and nothing
to find on PATH.

  macOS    CoreFoundation + Carbon TIS, so input-source ids read exactly as
           they do system-wide.
  Windows  user32/imm32. This also sees the hangul/latin toggle inside a CJK
           IME — state a tool that only reports the keyboard layout cannot
           report at all.

Linux has no OS-level API to call: the input method owns the state and only
exposes it over its own IPC.

  fcitx5   Answered in-process too, but over D-Bus rather than FFI: plain
           Lua on a session-bus socket, making the same
           org.fcitx.Fcitx.Controller1.CurrentInputMethod call that
           fcitx5-remote -n makes. Nothing to install, and PATH is never
           consulted — only $DBUS_SESSION_BUS_ADDRESS, falling back to
           /run/user/<uid>/bus.
  ibus     Still driven through the `ibus` CLI, which the plugin does not
           install: ibus lives on a private bus and answers GetGlobalEngine
           with a serialised engine descriptor rather than a name.

Note for ibus users: ibus does not expose the hangul/latin toggle inside
ibus-hangul at all, so with that toggle the label stays on 한. Configure the
한/영 key to switch ibus *engines* instead, or use fcitx5.

Run |:checkhealth| ime-status for guidance.

Neovim built against plain Lua rather than LuaJIT has no FFI. There the
macOS and Windows backends fall back to macism / im-select.exe if one
happens to be on PATH; the Linux backend uses no FFI and is unaffected.

==============================================================================
3. SETUP                                                     *ime-status-setup*

Call setup() once (this starts the polling timer): >lua

    require("ime-status").setup({})
<
With lazy.nvim, `opts = {}` does this for you.

==============================================================================
4. CONFIGURATION                                            *ime-status-config*

interval     (number, default 300)
             Polling interval in milliseconds.

insert_only  (boolean, default false)
             Only poll while in insert mode.

tool         (string|nil, default nil)
             For ibus, or to opt out of the native backend: name or absolute
             path of the input-source tool, used for both reading the current
             source and switching it, e.g. "/usr/bin/ibus". When nil
             the tool is auto-detected on the PATH for the current OS. Set
             this when Neovim is launched from a GUI and cannot see your shell
             PATH (see |ime-status-health|).

cmd          (string[]|nil, default nil)
             Low-level override of the *detection* command only, e.g.
             { "fcitx5-remote", "-n" }. The switch command is derived from
             cmd[1] unless `set_cmd` is given.

set_cmd      (string[]|fun(id):string[]|nil, default nil)
             Low-level override of the *switch* command only. A list gets the
             target id appended; a function receives the id and returns the
             full argv.

labels       (list, default 한/あ/中 rules)
             Ordered { match = <pattern>, text = <label> } rules. `match` is a
             case-insensitive substring tested against the raw backend id; the
             first match wins.

default      (string, default "EN")
             Label shown when no rule matches.

unknown      (string, default "?")
             Label shown when the backend returns no usable output.

format       (fun(label):string, default identity)
             Final transform applied before display.

auto_switch  (boolean, default false)
             Force the IME to `latin_source` on InsertLeave and on focusing the
             window in normal mode, so normal-mode motions are never swallowed
             by a CJK input method.

latin_source (string|nil, default nil)
             Input-source id auto_switch switches to. nil = OS default
             (macOS com.apple.keylayout.ABC, Linux keyboard-us on fcitx5
             or xkb:us::eng on ibus, Windows "en" — the FFI backend flips
             the IME to latin mode without changing the keyboard layout).
             The two Linux vocabularies are not interchangeable, so the
             default follows whichever backend answers.

restore_on_insert  (boolean, default false)
             On InsertEnter, restore the IME that was active before the last
             auto-switch.

pause_on_focus_lost  (boolean, default false)
             Stop polling while Neovim / the terminal is unfocused; resume and
             refresh on FocusGained.

5. API                                                         *ime-status-api*

require("ime-status").setup({opts})                          *ime-status.setup*
        Merge options, start polling, register autocmds. Idempotent. Never
        errors and never disables itself: when no backend can be found the
        plugin simply does nothing and keeps re-detecting, so a tool installed
        (or a PATH fixed) later starts working without restarting Neovim.

require("ime-status").get()                                    *ime-status.get*
        Return the current label string. Reads the cache; never blocks.

require("ime-status").component()                        *ime-status.component*
        Like get() but passed through `format`. Wire this into a statusline.

require("ime-status").refresh()                            *ime-status.refresh*
        Trigger one asynchronous detection now.

                                                      *ime-status-IMEStatusChanged*
A `User IMEStatusChanged` autocmd fires whenever the cached label changes.

:IMEStatusReload                                          *:IMEStatusReload*
        Drop the cached backend probe and re-detect now, reporting what was
        found. Useful right after installing an input-source tool.

==============================================================================
6. HEALTH                                                   *ime-status-health*

  :checkhealth ime-status

Reports which backend is active (the native FFI backend on macOS and Windows,
the native D-Bus backend when fcitx5 answers on the session bus, otherwise a
supported input-source tool on the PATH), whether that tool can switch as well
as report, and, when none is available, how to install one.

fcitx5 reports the input method of the *focused* client, so with nothing
focused it answers with an empty name and the label falls back to `unknown`
("?"). That is expected while Neovim is in the background. A label that never
becomes anything else usually means the terminal is not a fcitx5 client --
check GTK_IM_MODULE / QT_IM_MODULE / XMODIFIERS.

The PATH caveat below applies to ibus — and on macOS/Windows only once you
pinned `tool`/`cmd` or run a Neovim without LuaJIT. It never applies to the
fcitx5 backend, which reads the bus address, not PATH. If the tool works in a
terminal but not here, the cause is almost always PATH: Neovim launched from
a GUI (a .desktop launcher, Neovide, a macOS .app or Automator action) does
not read your shell rc files, so directories such as /usr/local/bin are
missing. Check `:echo $PATH`, then either fix the launcher's environment or
set `tool` to an absolute path.
